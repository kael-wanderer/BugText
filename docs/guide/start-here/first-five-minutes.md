Three things are worth trying first: opening a folder of notes, writing a note with its preview beside it, and finding things with the command palette.

## When to use it

- Right after you install BugText.
- When you want a quick feel for the app before exploring further.

## How to use it

### Open a folder

The first time BugText opens, a **Welcome to BugText** card offers **Open Folder**, **New Note** and **Show Shortcuts**.

1. Click **Open Folder** (or press <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>O</kbd>) and choose a folder that holds your notes, or an empty folder to start one.
2. The folder's files appear in the Explorer on the left. Click a file to open it in a tab.

BugText remembers the folder, your tabs and where you were in each one for next time.

### Write a first note

1. Press <kbd>⌘</kbd> <kbd>N</kbd> for a new note.
2. Type a heading such as `# My first note` and a few lines. Select a word and use the format bar above the editor for **Bold**, **Italic**, **Link** and the rest.
3. Press <kbd>⌘</kbd> <kbd>P</kbd> to show the preview beside the editor, or <kbd>⌘</kbd> <kbd>E</kbd> for Reading view, which shows only the rendered note.
4. Type `- [ ] Try BugText` for a checklist item. In the preview, click its box to tick it.
5. Press <kbd>⌘</kbd> <kbd>S</kbd> and choose a name. The note is a `.md` file in your folder.

### Find anything with ⌘K

Press <kbd>⌘</kbd> <kbd>K</kbd>, or click **Go to file** in the middle of the title bar, and start typing:

- Part of a file name opens that file. You can also paste a path; add `:42` to open it at line 42.
- Part of a command name runs it, for example `daily` for **Open Daily Note** or `graph` for **Graph: Open Local Graph**.

To search inside every file instead, press <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>F</kbd>.

> [!TIP]
> **Help** ▸ **BugText Help** opens a short built-in help note as a tab. **View** ▸ **Keyboard Shortcuts…** lists every shortcut and lets you change any of them.

## What it will not do

- Closing BugText with unsaved changes does not lose them: they come back as recovery drafts the next time it opens. See [History, recovery and Git](../notes/history-and-git.md).
